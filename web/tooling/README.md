# Сжатые представления сборки

`precompressedAssets.ts` создаёт рядом с хешированными GLB, JS, CSS и SVG файлы
`.br` (Brotli quality 6) и `.gz` (gzip level 9). Исходные байты и URL не меняются.
Сжатие выполняет `node:zlib` при сборке; браузер распаковывает HTTP-ответ штатно,
без дополнительных декодеров, WASM или изменений CSP.

Минимальный размер — 4 КиБ. Каждое представление сохраняется только при экономии
не менее 10% и 512 байт. Уже сжатые изображения/шрифты, маленькие файлы и файлы
без хеша пропускаются. Ассеты обрабатываются последовательно, чтобы несколько
моделей не увеличивали пиковое потребление памяти при сборке.

`server/web_app.py` выбирает доступное представление по `Accept-Encoding`.
Явные веса и запреты `q=0`, wildcard и регистр соблюдаются; неуказанный `identity`
остаётся резервным вариантом после разрешённых кодировок. Ответы всех вариантов,
включая `identity` и `304`, содержат `Vary: Accept-Encoding`. Самостоятельные URL
`.br`/`.gz` не открываются маршрутом ассетов.

Используются небольшие переопределения методов закреплённого `aiohttp 3.14.2`
`FileResponse`: выбор файла, установка кодировки без перезаписи `Vary` и
квалификация ETag суффиксом варианта. Обработка условных запросов, диапазонов,
HEAD и отправка файла остаются в aiohttp. Суффикс ETag исключает совпадение
валидаторов разных представлений даже при одинаковых размере и времени файла.
Строгий ETag в `If-Range` сравнивается с выбранным представлением; при несовпадении,
слабом или некорректном теге возвращается весь файл. `If-Range` с HTTP-датой
обрабатывается штатным кодом aiohttp.
При обновлении aiohttp эти переопределения проверяют вместе с HTTP-тестами.

`precompressedAssets.test.ts` проверяет точное восстановление байтов,
детерминированность, пороги и настоящую сборку Vite. `tests/test_web_app.py`
проверяет согласование представлений, кэширование, HEAD, диапазоны и условные
запросы на синтетических файлах.

# zod до первой схемы

`configuredZod.ts` останавливает сборку, если `zod` во время выполнения импортирует какой-либо
модуль, кроме `src/core/zod.ts`; импорт одних типов в бандл не попадает и разрешён.
`src/core/zod.ts` включает `jitless` и отдаёт `z`. Импорт `z` из него делает настройку
зависимостью каждого модуля со схемами, и rolldown выполняет её первой, в каком бы чанке модуль
ни оказался. Без `jitless` zod при первой объектной схеме пробует `new Function`, а строгий
`script-src 'self'` сообщает об этом как о нарушении CSP, хотя исключение zod перехватывает.

`configuredZod.test.ts` собирает форму, которая сломалась 2026-10-06: модуль, общий для входа и
ленивого экрана, строит схему при загрузке из собственного чанка. Сборка загружается в отдельном
процессе Node, где `Function` бросает исключение, как под CSP. Тест проверяет, что с
`src/core/zod.ts` вызовов нет, что пробу ненастроенного zod видно и что прямой импорт сборка
отклоняет.

# Имена файлов, которые отдаёт сервер

`server/web_app.py` отдаёт хешированные файлы сборки только по маршруту `/assets/<имя>`: имя
начинается с буквы или цифры, дальше буквы, цифры, `.`, `_` и `-` (`ASSET_NAME`), а тип есть в
`MEDIA`. Остальное получает 404 — устаревший чанк должен падать явно, а не загружать приложение
снова. Rolldown сам заменяет `\0` виртуального модуля на `_`, и с 2026-10-06 (PR 93) общий
вспомогательный модуль Vue выходил отдельным чанком `_plugin-vue_export-helper-<hash>.js`:
сервер отвечал 404, `AppShell` не загружался, страница оставалась пустой.

`servedAssets.ts` задаёт `sanitizeFileName`: недопустимые символы становятся `_`, начальные
не-буквы и не-цифры отбрасываются (`plugin-vue_export-helper-<hash>.js`). В конце сборки он же
проверяет каждый файл в `assets/` (сжатые `.br`/`.gz` — по их исходному файлу) и останавливает
сборку, если сервер его не отдаст. Копия маршрута для сборки — `servedAssets.json`;
`tests/test_web_app.py` держит её равной `ASSET_NAME` и `MEDIA` сервера, поэтому этот файл входит и
в линию `unit` (`.forgejo/lanes.sh`).

`servedAssets.test.ts` собирает два ленивых SFC со scoped-стилями — форму, в которой появился
отдельный чанк вспомогательного модуля, — и проверяет его имя, отказ сборки на файле, который
сервер не отдаст, и на другом каталоге ассетов.
